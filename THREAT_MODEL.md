# Threat model

Method: STRIDE with explicit process/file-descriptor lifecycle analysis. This is a design review, not proof of security. Native attack fixtures are benign, bounded tests on an owned disposable Linux environment; do not use real malware, exploit live services or run on a shared production host.

## Assets, actors and assumptions
Assets: host files/secrets, supervisor availability, approved executable identity, guest input/output confidentiality, immutable results, evidence integrity and host resource budget. Trusted actors: host kernel/administrator, current local operator, installed supervisor/launcher/toolchain. Untrusted actors: guest executable, guest input/output, client-provided bounded fields, PR code on untrusted branches. The authorized local client shares the operator UID; isolation from a malicious same-UID host process is NOT claimed.

Trust zones: host operator and control plane; exec-separated trusted launcher during setup; kernel-restricted guest processes; quiescent untrusted artifacts; public sanitized documentation/evidence. Entry points: Unix framing/JSON, profile/input staging, launch control socket and SCM_RIGHTS, guest syscalls, stdio, artifact names/bytes, persisted state, dependencies and CI. No browser, HTTP listener, model API, OAuth authority or cross-tenant remote platform exists in core.

## Mandatory control decisions
Authentication is local UID admission, not bearer tokens. Authorization is approved profile + bounded inputs, not arbitrary host authority. No secrets are passed to guests; fixed environment only. Exporter never follows guest-controlled links. Landlock does not retroactively revoke previously opened descriptors: descriptor closure is separately necessary. A seccomp allowlist is not a complete sandbox; combine with namespaces, filesystem restrictions and resource/lifecycle controls. cgroup.kill is a kill request, not proof of an immediate terminal outcome.

Kernel-level exploits, hardware side channels, malicious root/host owner, physical attackers, secure deletion, dynamic package managers and network-enabled tools are outside the stated model. OS patching and a disposable test host are prerequisites. No numeric attack-detection rate or blanket 'secure' claim is permitted; enumerate tests and boundaries instead.

## Release and disclosure
Document supported kernel/ABI/profile versions and all known limitations. Enable GitHub private vulnerability reporting when available. Until a private reporting channel exists, do not solicit exploit details in public issues; use the repository security contact mechanism without exposing private contact details. There is no promised response SLA. Material unresolved findings block the relevant release claim. Independent reviewer starts read-only, records findings before the integrator changes code, then retests fixes.
